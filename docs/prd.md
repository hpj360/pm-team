## 1. 产品概述

### 1.1 项目背景

网络安全红方业务需要处理海量安全相关文件，包括但不限于：渗透测试报告、漏洞扫描结果、流量捕获文件（PCAP）、日志文件、恶意样本、配置文件、目标资产信息等。这些文件是红方业务的核心数据资产，其管理效率直接影响安全测试工作的质量和效率。

随着红方业务的不断拓展，面临的主要挑战包括：文件数量庞大且增长迅速，传统管理方式难以满足存储需求；文件类型多样，缺乏统一的解析和分析手段；信息检索困难，无法快速定位所需资料；文件之间缺乏关联分析，难以形成完整的情报链条；敏感文件缺乏有效的安全管控，存在数据泄露风险；红方任务与文件、目标、报告之间的关联管理缺失，难以形成闭环的业务流程。

因此，亟需建设一个专业的红方文件汇聚平台，实现文件的统一存储、智能解析、高效检索、安全分析和目标画像刻画，并支撑红方任务全生命周期管理，全面提升红方业务的信息化水平。

### 1.2 产品定位

网络安全红方文件汇聚平台是一个面向网络安全红方团队的专业文件管理与任务协作平台，定位于为红方业务提供全生命周期的文件管理、任务协作和分析服务。平台采用分布式多租户架构设计，支持海量文件存储和高并发访问，通过人工智能技术实现智能化文件分析和语义检索，帮助红方团队提升工作效率和情报分析能力。

### 1.3 产品目标

#### 1.3.1 业务目标

| 目标项 | 描述 | 衡量指标 |
|-------|------|---------|
| 统一存储 | 建立统一的文件存储平台，实现文件的集中管理 | 文件集中率 ≥ 95% |
| 高效检索 | 提供多维度的混合检索能力，快速定位目标文件 | 检索响应时间 P99 < 500ms |
| 智能分析 | 自动化文件解析和安全分析，提取关键信息 | 分析准确率 ≥ 90% |
| 目标画像 | 基于文件信息刻画目标特征，形成完整的情报画像 | 画像覆盖率 ≥ 80% |
| 安全可控 | 实现细粒度的访问控制和审计，保障数据安全 | 安全事件 ≤ 1次/年 |
| 任务协作 | 支撑红方任务全生命周期管理 | 任务闭环率 ≥ 95% |

#### 1.6.2 关键架构说明

1. **多租户隔离**：所有应用服务和数据存储均通过 `tenant_id` 实现租户隔离，数据库表统一包含 `tenant_id` 字段。
2. **微服务化**：应用服务层采用微服务架构，各服务独立部署、独立扩展，通过REST API或消息队列通信。
3. **安全合规**：网关层集成国密算法（SM2/SM3/SM4），所有传输使用TLS加密，敏感数据加密存储。
4. **可观测性**：全链路监控、日志聚合、链路追踪三位一体，保障系统可观测性。

## 2. 用户角色分析

### 2.1 角色定义

平台预置 5 个标准角色，统一覆盖红方业务的全部场景：

| 角色名称 | 角色描述 | 占比 |
|---------|---------|------|
| 红方操作员 | 执行渗透测试、漏洞挖掘等安全测试任务的一线人员 | 60% |
| 红方分析师 | 负责安全分析、情报分析、报告编写的分析人员 | 20% |
| 红方管理员 | 负责团队管理、任务分配、资源调度的管理人员（业务管理） | 10% |
| 系统管理员 | 负责平台运维、配置管理、用户管理的运维人员（系统管理） | 5% |
| 安全审计员 | 负责安全审计、合规检查的审计人员 | 5% |

**角色边界说明：**
- **红方管理员**：负责业务管理（任务、团队、报告、资源），对用户管理只有只读权限。
- **系统管理员**：负责系统管理（用户、角色、配置、存储、备份），拥有用户管理的写权限。

### 2.4 数据分类分级

平台所有数据按以下5级分类管理：

| 等级 | 名称 | 描述 | 示例 | 保护措施 |
|-----|------|------|------|---------|

| L3 | 秘密 | 包含敏感信息的数据 | 渗透测试报告、目标资产信息 | RBAC+审计日志+加密传输 |

| L5 | 绝密 | 包含核心机密的数据 | 客户核心资产清单、APT情报 | 严格审批+专人访问+全审计+国密加密 |

**数据分级规则：**
- 文件上传时由用户选择等级，系统根据内容自动建议
- 不同等级的数据访问需满足对应的权限和认证要求
- L4/L5级数据的下载、分享、导出需二次审批和审计

### 3.1 文件上传模块

#### 3.1.1 模块概述

#### 3.1.3 详细功能说明

##### F3.1.1 单文件上传

**功能描述：**

用户通过Web界面或API上传单个文件，系统接收文件并存储到对象存储系统，同时记录文件元数据信息。单文件上传是整个上传模块的基础功能，其他上传功能均基于此功能扩展实现。

**业务规则：**

| 规则编号 | 规则描述 |
|---------|---------|
| BR3.1.1.1 | 单个文件大小不超过50GB |
| BR3.1.1.2 | 支持的文件类型包括：文档类（PDF、Word、Excel、PPT、TXT）、压缩包（ZIP、RAR、7z、TAR）、镜像文件（ISO、IMG）、流量文件（PCAP、PCAPNG）、日志文件（LOG、JSON、XML）、代码文件（各类编程语言源码）、配置文件（CONF、INI、YAML）、红方工具产出文件（Burp/Nmap/Nessus/Metasploit/Cobalt Strike等）等 |
| BR3.1.1.3 | 文件名长度不超过255个字符，不支持特殊字符（`/ \ : * ? " < > |`） |
| BR3.1.1.4 | 上传前需进行用户身份认证和权限校验 |
| BR3.1.1.5 | 上传完成后自动计算文件哈希值（MD5、SHA256、SM3） |
| BR3.1.1.6 | 上传时需指定数据分类分级（L1-L5），默认L2内部 |

**输入输出：**

| 类型 | 内容 |
|-----|------|
| 输入 | 文件内容、文件名、目标目录、标签（可选）、描述（可选）、分类分级 |
| 输出 | 文件ID、上传状态、存储路径、哈希值 |

**异常处理：**

| 异常场景 | 处理方式 |
|---------|---------|
| 文件类型不支持 | 返回错误提示，列出支持的文件类型 |
| 文件大小超限 | 返回错误提示，建议使用分片上传 |
| 存储空间不足 | 返回错误提示，联系管理员扩容 |
| 网络中断 | 支持断点续传，提示用户继续上传 |
| 权限不足 | 返回权限错误，提示联系管理员 |

##### F3.1.2 大文件分片上传

**功能描述：**

对于大文件（>100MB），系统自动采用分片上传方式，将文件分割成多个小块并发上传，提高上传成功率和速度。分片上传可以有效解决大文件上传失败的问题，同时支持断点续传功能。

**业务规则：**

| 规则编号 | 规则描述 |
|---------|---------|
| BR3.1.2.1 | 文件大小超过100MB自动启用分片上传 |
| BR3.1.2.2 | 默认分片大小为10MB，可根据网络情况动态调整 |
| BR3.1.2.3 | 每个分片独立计算哈希值（SM3），用于完整性校验 |
| BR3.1.2.4 | 支持分片并发上传，默认并发数为4 |
| BR3.1.2.5 | 所有分片上传完成后，服务端进行文件合并 |
| BR3.1.2.6 | 合并完成后校验整体文件哈希值（SHA256+SM3），确保完整性 |

**分片上传流程：**

```
第一步：初始化上传
客户端发送文件信息（文件名、大小、整体哈希值）
服务端返回上传ID和分片大小

第二步：分片上传（并发）
客户端将文件分割成多个分片
并发上传各分片，每个分片携带序号和分片哈希值
服务端接收分片并存储，返回确认信息

第三步：完成上传
客户端发送完成请求
服务端合并所有分片
校验整体哈希值，返回最终结果
```

##### F3.1.3 批量上传

**功能描述：**

支持用户一次性上传多个文件或整个文件夹，系统自动处理文件队列，提供整体进度显示。批量上传功能可以大幅提升用户的工作效率，特别适用于需要同时上传大量测试报告和扫描结果的场景。

**业务规则：**

| 规则编号 | 规则描述 |
|---------|---------|
| BR3.1.3.1 | 单次批量上传文件数量不超过1000个 |
| BR3.1.3.2 | 单次批量上传总大小不超过100GB |
| BR3.1.3.3 | 支持文件夹结构保留，自动创建对应目录结构 |
| BR3.1.3.4 | 批量上传支持暂停、继续、取消操作 |
| BR3.1.3.5 | 单个文件上传失败不影响其他文件继续上传 |
| BR3.1.3.6 | 批量上传完成后生成上传报告，列出成功和失败的文件 |
| BR3.1.3.7 | **限制规则优先级**：单文件大小限制 > 批量数量限制 > 批量总大小限制 > 租户配额限制；任一限制触发时拒绝上传并提示具体原因 |

##### F3.1.4 断点续传

**功能描述：**

当上传过程中断（网络故障、客户端崩溃等），用户可以在恢复后继续上传，避免从头开始。断点续传功能对于大文件上传尤为重要，可以显著提升用户的使用体验。

**业务规则：**

| 规则编号 | 规则描述 |
|---------|---------|
| BR3.1.4.1 | 上传中断后，服务端保留已上传的分片24小时 |
| BR3.1.4.2 | 客户端恢复后，查询已上传分片列表，继续上传未完成的分片 |
| BR3.1.4.3 | 分片上传记录存储在Redis中，设置过期时间 |
| BR3.1.4.4 | 支持跨设备续传（同一用户不同终端） |
| BR3.1.4.5 | 续传时需验证文件哈希值，防止文件被篡改 |

##### F3.1.5 秒传

**功能描述：**

上传前客户端先分片计算文件SHA256哈希值，然后查询服务端是否已存在相同哈希值的文件。若命中则建立引用关系实现秒传；若未命中则进行分片上传。秒传功能可以大幅提升重复文件的处理效率，节省存储空间和带宽资源。

**业务规则：**

| 规则编号 | 规则描述 |
|---------|---------|
| BR3.1.5.1 | 秒传基于文件SHA256+SM3双重哈希值判断 |
| BR3.1.5.2 | 相同哈希值的文件共享同一份物理存储 |
| BR3.1.5.3 | 删除文件时采用引用计数，物理文件在引用为0时删除 |
| BR3.1.5.4 | 秒传文件仍需记录独立的元数据信息 |
| BR3.1.5.5 | 秒传结果需明确告知用户，避免用户困惑 |
| BR3.1.5.6 | 秒传不跨租户生效，租户间数据严格隔离 |

**秒传标准流程：**

```
第一步：客户端分片计算哈希
客户端将文件分片（10MB/片）
并发计算每个分片的SHA256
汇总得到文件整体SHA256

第二步：查询服务端
客户端发送文件整体SHA256到服务端
服务端在当前租户范围内查询哈希是否存在

第三步：分支处理
分支A（命中）：服务端返回秒传成功
  - 建立文件引用关系
  - 复制元数据信息
  - 返回文件ID
  - 流程结束

分支B（未命中）：进入分片上传流程
  - 客户端初始化上传任务
  - 上传分片（已计算的分片哈希可复用）
  - 服务端合并分片
  - 校验整体哈希
  - 返回文件ID
```

#### 3.1.6 文件状态机

文件状态机采用**三字段独立状态机**设计，存储、解析、分析三个流程相互独立、互不阻塞。任意流程失败不影响其他流程执行，支持精准定位失败环节、按状态过滤检索和独立重试。

**storage_status（存储状态机）：**

```
uploading(0) ──上传完成──> uploaded(1) ──软删除──> deleted(2)
                              ▲                       │
                              │──恢复（回收站恢复）──┘
                              │
                              └──硬删除：物理文件引用计数减1，元数据标记永久删除
```

| 状态值 | 状态名 | 说明 |
|-------|-------|------|
| 0 | uploading | 上传中（分片未合并完成） |
| 1 | uploaded | 已上传（存储完成，可被检索、解析、分析） |
| 2 | deleted | 已删除（软删除进入回收站，可恢复；硬删除引用计数为0时清除物理文件） |

**parse_status（解析状态机）：**

```
pending(0) ──触发解析──> parsing(1) ──成功──> success(2)
                            │
                            ├──失败──> failed(3) ──重试──> parsing(1)
                            │
                            └──不支持解析/非文本格式──> skipped(4)
```

| 状态值 | 状态名 | 说明 |
|-------|-------|------|
| 0 | pending | 待解析（文件上传完成，等待解析任务调度） |
| 1 | parsing | 解析中（解析器正在执行） |
| 2 | success | 解析成功（文本、实体、元数据均已提取） |
| 3 | failed | 解析失败（可重试，记录错误信息） |
| 4 | skipped | 跳过解析（不支持该格式或无需解析，如纯图片不需向量化前置OCR） |

**analysis_status（分析状态机）：**

```
pending(0) ──触发分析──> analyzing(1) ──完成──> completed(2)
                             │
                             ├──失败──> failed(3) ──重试──> analyzing(1)
                             │
                             └──无需分析（已为已知安全文件）──> skipped(4)
```

| 状态值 | 状态名 | 说明 |
|-------|-------|------|
| 0 | pending | 待分析（解析完成或文件就绪，等待分析任务调度） |
| 1 | analyzing | 分析中（恶意检测/漏洞提取/沙箱等分析器执行中） |
| 2 | completed | 分析完成（汇总所有分析结果） |
| 3 | failed | 分析失败（可重试，记录错误信息） |
| 4 | skipped | 跳过分析（用户手动跳过或重复文件已分析过） |

**状态联动规则：**
- storage_status 必须为 `uploaded(1)` 才能触发 parse_status 和 analysis_status 流程
- parse_status 为 `success(2)` 是 analysis_status 触发的推荐前置条件（不强制，可独立分析原始文件）
- 三个状态字段独立更新、独立查询，互不阻塞
- 重试操作只重置对应字段为 pending，不影响其他字段

### 3.2 文件解析模块

#### 3.2.1 模块概述

文件解析模块负责对上传的文件进行自动解析，提取文件内容、元数据和结构化信息，为后续的检索和分析提供数据基础。该模块需要支持多种文件格式的解析，包括文档、压缩包、流量文件、日志文件、配置文件等，同时还需要进行实体识别和向量化处理，为智能检索提供支持。**OCR识别调整为P0优先级**，因为图片格式的漏洞截图、扫描件等是红方业务常见文件，向量化处理依赖文本内容，需先通过OCR提取文本。

|---------|---------|-------|---------|

| F3.2.2 | 文档解析 | P0 | 解析PDF、Word、Excel、PPT等文档，提取文本内容 |
| F3.2.3 | 压缩包解析 | P0 | 解析ZIP、RAR、7z等压缩包，提取文件列表和内容 |
| F3.2.4 | 流量文件解析 | P0 | 解析PCAP、PCAPNG流量文件，提取网络会话信息 |
| F3.2.5 | 日志文件解析 | P0 | 解析各类日志文件，提取结构化日志信息 |
| F3.2.6 | 配置文件解析 | P1 | 解析各类配置文件，提取配置项信息 |

#### 3.2.3 详细功能说明

##### F3.2.1 格式识别

**功能描述：**

通过文件魔数（Magic Number）和内容特征识别文件的真实格式，防止用户通过修改扩展名伪装文件类型。格式识别是文件解析的第一步，只有正确识别文件格式，才能选择正确的解析器进行处理。

**业务规则：**

| 规则编号 | 规则描述 |
|---------|---------|
| BR3.2.1.1 | 优先使用文件魔数识别格式，而非扩展名 |
| BR3.2.1.2 | 支持常见文件格式的魔数识别（PDF、ZIP、RAR、PNG、JPEG等） |
| BR3.2.1.3 | 识别结果与扩展名不一致时，记录警告日志 |
| BR3.2.1.4 | 无法识别的格式标记为"未知"，仍允许存储 |
| BR3.2.1.5 | 格式识别结果存储在文件元数据中 |

**支持的文件格式：**

| 类别 | 格式 | 魔数（部分） |
|-----|------|------------|
| 文档 | PDF | 25 50 44 46 |
| 压缩包 | ZIP | 50 4B 03 04 |
| 压缩包 | RAR | 52 61 72 21 |
| 图片 | PNG | 89 50 4E 47 |
| 图片 | JPEG | FF D8 FF |
| 流量 | PCAP | D4 C3 B2 A1 |
| 流量 | PCAPNG | 0A 0D 0D 0A |

##### F3.2.9 实体识别

**功能描述：**

从解析的文本内容中识别关键实体，包括IP地址、域名、邮箱、哈希值、URL等安全相关实体。实体识别是关联分析的基础，通过提取文件中的实体信息，可以建立文件之间的关联关系。

**业务规则：**

| 规则编号 | 规则描述 |
|---------|---------|
| BR3.2.9.1 | 识别IPv4和IPv6地址 |
| BR3.2.9.2 | 识别域名和子域名 |
| BR3.2.9.3 | 识别邮箱地址 |
| BR3.2.9.4 | 识别MD5、SHA1、SHA256、SM3等哈希值 |
| BR3.2.9.5 | 识别URL和路径 |
| BR3.2.9.6 | 识别CVE编号、CNVD编号等漏洞标识 |
| BR3.2.9.7 | 识别端口号和服务名称 |
| BR3.2.9.8 | 实体识别结果存储到数据库，建立实体索引 |
| BR3.2.9.9 | 实体入库前进行标准化去重，避免同一实体多种表示形式导致重复 |

**实体去重策略：**

| 实体类型 | 标准化方法 | 去重比较规则 | 示例 |
|---------|----------|------------|------|
| IP地址 | 标准格式化：IPv4去除前导0；IPv6展开并转全小写 | 标准格式化后比较 | `192.168.001.001` → `192.168.1.1` |
| 域名 | 统一转小写 + 去除末尾点 | 标准化后比较 | `Example.COM.` → `example.com` |
| CVE编号 | 统一格式：CVE-YYYY-NNNN（年份4位、编号补0至4位） | 标准格式后比较 | `CVE-2024-1` → `CVE-2024-0001` |
| CNVD编号 | 统一格式：CNVD-YYYY-NNNN | 标准格式后比较 | `cnvd-2024-1234` → `CNVD-2024-1234` |
| 邮箱 | 统一转小写 | 标准化后比较 | `User@Example.COM` → `user@example.com` |
| 哈希值 | 统一转小写 | 标准化后比较 | `ABCDEF...` → `abcdef...` |
| URL | 协议转小写、域名转小写、去除默认端口和尾部斜杠 | 标准化后比较 | `HTTP://Example.COM:80/` → `http://example.com` |

**实体识别正则表达式（标准regex语法）：**

| 实体类型 | 正则表达式 |
|---------|-----------|
| IPv4 | `\b(?:\d{1,3}\.){3}\d{1,3}\b` |
| IPv6 | `\b(?:[0-9a-fA-F]{1,4}:){7}[0-9a-fA-F]{1,4}\b` |
| 域名 | `\b(?:[a-zA-Z0-9](?:[a-zA-Z0-9-]{0,61}[a-zA-Z0-9])?\.)+[a-zA-Z]{2,}\b` |
| 邮箱 | `\b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}\b` |
| MD5 | `\b[a-fA-F0-9]{32}\b` |
| SHA1 | `\b[a-fA-F0-9]{40}\b` |
| SHA256 | `\b[a-fA-F0-9]{64}\b` |
| SM3 | `\b[a-fA-F0-9]{64}\b` |
| URL | `https?://[^\s<>"]+` |
| CVE | `CVE-\d{4}-\d{4,}` |
| CNVD | `CNVD-\d{4}-\d{4,}` |
| 端口号 | `\b(?:端口|port)[:\s]+(\d{1,5})\b` |

##### F3.2.10 向量化处理

**功能描述：**

将文件内容转换为向量表示，用于语义检索和相似度计算。向量化处理是实现语义检索的关键技术，通过将文本内容映射到高维向量空间，可以实现基于语义相似度的检索。

**业务规则：**

| 规则编号 | 规则描述 |
|---------|---------|
| BR3.2.10.1 | 使用预训练的中文语义向量模型（BGE/M3E） |
| BR3.2.10.2 | 向量维度为768或1024 |
| BR3.2.10.3 | 对文本内容进行分块处理，每块不超过512个token |
| BR3.2.10.4 | 每个文本块生成一个向量，建立向量索引 |
| BR3.2.10.5 | 向量存储到Milvus向量数据库 |

#### 3.2.4 解析流程

```
文件上传完成
    |
    v
格式识别 -----> 记录格式信息
    |
    v
路由到对应解析器
    |
    +---> 文档解析器 -----> 提取文本、表格、图片
    +---> 压缩包解析器 ---> 提取文件列表、递归解析
    +---> 流量解析器 -----> 提取会话、协议信息
    +---> 日志解析器 -----> 提取结构化日志
    +---> 配置解析器 -----> 提取配置项
    +---> 图片解析器 -----> OCR识别（向量化前置依赖）
    +---> 红方工具解析器 -> 提取结构化测试结果
    |
    v
实体识别 -----> 提取IP、域名、哈希等实体
    |
    v
向量化处理 -----> 生成语义向量
    |
    v
存储结果
    +---> PostgreSQL (元数据、实体)
    +---> Elasticsearch (全文索引)
    +---> Milvus (向量索引)
    +---> Neo4j (实体关系)
```

**业务规则：**

| 规则编号 | 规则描述 |
|---------|---------|
| BR3.3.4.1 | 同时执行三种检索，合并结果 |
| BR3.3.4.2 | 采用加权融合策略计算最终得分 |
| BR3.3.4.3 | 默认权重：全文检索0.4，向量检索0.4，元数据匹配0.2 |
| BR3.3.4.4 | **支持按用户/场景配置权重**（系统配置项 `search.hybridWeights`，格式 `w1,w2,w3`）；支持预设场景模板（如情报分析场景0.3/0.5/0.2、漏洞检索场景0.5/0.3/0.2） |
| BR3.3.4.5 | 结果去重，按综合得分排序 |
| BR3.3.4.6 | 用户级权重配置优先于场景模板，场景模板优先于系统默认值 |

**融合算法：**

```
综合得分 = w1 × 全文检索得分 + w2 × 向量检索得分 + w3 × 元数据匹配得分

其中：
- w1 + w2 + w3 = 1
- 默认 w1 = 0.4, w2 = 0.4, w3 = 0.2
- 各项得分归一到 [0, 1] 区间
```

| 银行卡号 | 保留前4位+后4位，中间替换为* | `6222021234567890` → `6222********7890` | 按银行卡长度脱敏 |
| 密码/密钥 | 全部替换为****** | `password123` → `******` | 密钥、Token、密码全部脱敏 |
| API密钥 | 保留前4位+后4位，中间替换为* | `AKIA1234567890ABC` → `AKIA*******ABC` | 各种API Key脱敏 |
| 数据库连接串 | 用户名密码部分脱敏 | `mysql://user:pass@host/db` → `mysql://user:******@host/db` | 连接字符串中凭证脱敏 |
| IPv4地址 | 保留前两段，后两段替换为*.* | `192.168.1.1` → `192.168.*.*` | 仅L4/L5数据预览时脱敏 |
| 私钥文件 | 内容全部替换为****** | `-----BEGIN RSA PRIVATE KEY-----...` → `******` | 全部脱敏，仅授权下载 |

**敏感信息识别正则：**

| 类型 | 正则表达式 |
|-----|-----------|
| 手机号 | `1[3-9]\d{9}` |
| 身份证号 | `\d{17}[\dXx]` |
| 邮箱 | `\b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}\b` |
| API密钥 | `(?i)(api[_-]?key|secret[_-]?key)\s*[:=]\s*[A-Za-z0-9+/=]{32,}` |

##### F3.4.6 沙箱动态分析

**功能描述：**

在隔离的沙箱环境中动态执行可执行文件、文档、脚本等，分析其运行时行为特征，发现静态分析无法发现的恶意行为。沙箱分析作为独立子模块设计，与静态检测引擎互补，包含**隔离环境、资源限制、行为监控、报告生成、清理回收**五个子模块。

**业务规则：**

| BR3.4.6.3 | 沙箱环境完全隔离，禁止访问生产网络 |

**沙箱子模块设计：**

###### ① 隔离环境设计

| 隔离方案 | 适用场景 | 隔离强度 | 性能开销 | 说明 |
|---------|---------|---------|---------|------|
| gVisor | Linux通用样本分析 | 中（用户态内核） | 低 | 兼容性好，适合大规模批量分析 |
| Kata Containers | 高危样本/未知样本 | 高（硬件级虚拟化） | 中 | 基于轻量级虚拟机，强隔离 |
| Docker + seccomp/AppArmor | 普通样本快速分析 | 中低 | 极低 | 容器化快速部署，适合规模化 |
| KVM/QEMU虚拟机 | Windows样本/Office宏样本 | 高（完全虚拟化） | 中高 | 完整OS环境，支持复杂样本 |

**隔离环境配置：**
- 网络隔离：通过netns命名空间隔离网络，仅允许访问受控的DNS/HTTP代理
- 文件系统隔离：使用overlayfs/独立磁盘镜像，宿主文件系统不可写
- 进程隔离：cgroups + namespace双重隔离
- 系统调用过滤：seccomp-bpf白名单过滤

###### ② 资源限制

| 资源类型 | 限制策略 | 默认值 | 说明 |

| 磁盘 | 配额限制 | 1GB可写空间 | 防止磁盘填充攻击 |

| 文件描述符 | ulimit限制 | 1024 | 防止资源耗尽 |

- 推理服务以微服务形式部署在K8s集群
- 模型文件存储在共享存储（MinIO），启动时按需加载
- GPU节点使用nvidia.com/gpu资源配额调度
- 支持模型推理服务的水平扩展（HPA），按QPS自动伸缩

###### ④ 模型更新机制

| 更新机制 | 触发条件 | 切换策略 | 说明 |
|---------|---------|---------|------|
| A/B测试 | 新模型上线前 | 按50%/50%流量对比1-7天 | 对比准确率、延迟等指标，决定是否全量 |
| 灰度发布 | A/B测试通过 | 10% → 30% → 50% → 100% | 每阶段观察1-2天，异常自动回滚 |
| 自动回滚 | 推理延迟P99 > 200ms或准确率下降>5% | 立即回滚到上一稳定版本 | 触发条件自动检测，无需人工干预 |
| 手动回滚 | 业务方主动触发 | 立即切换到指定版本 | 适用于业务异常或发现新版本缺陷 |
| 定时更新 | 模型有新版本发布 | 由系统管理员审批后执行 | AI工程师提交新版本，系统管理员审批上线 |

**A/B测试决策指标：**
- 准确率（precision/recall）：新版本准确率不能低于旧版本2%
- 推理延迟：新版本P99延迟不能超过旧版本120%
- 吞吐量：新版本QPS不能低于旧版本90%
- 异常率：新版本错误率不能超过0.5%

### 3.8 文件下载模块

#### 3.8.1 模块概述

文件下载模块负责将平台存储的文件提供给用户下载，支持单文件下载、批量下载、断点续传下载、限流下载、下载审计和下载水印等功能。该模块需要支持500 QPS的并发下载能力，确保下载过程的安全可控和可追溯。

#### 3.8.2 功能列表

| 功能编号 | 功能名称 | 优先级 | 功能描述 |
|---------|---------|-------|---------|
| F3.8.1 | 单文件下载 | P0 | 支持单个文件下载，含进度显示 |

| F3.8.4 | 限流下载 | P0 | 支持下载速率限制，防止带宽滥用 |
| F3.8.5 | 下载审计 | P0 | 记录所有下载行为，含用户、时间、IP、文件 |

| F3.8.7 | 下载审批 | P1 | L4/L5级文件下载需审批 |

#### 3.8.3 详细功能说明

##### F3.8.1 单文件下载

**功能描述：**

用户下载单个文件，系统从对象存储读取文件并返回给用户。下载过程支持进度显示、断点续传和限流控制。

**业务规则：**

| 规则编号 | 规则描述 |
|---------|---------|
| BR3.8.1.1 | 下载前需验证用户权限和数据分级 |
| BR3.8.1.2 | L4/L5级文件下载需二次审批 |
| BR3.8.1.3 | 恶意文件下载需管理员审批 |
| BR3.8.1.4 | 下载响应时间 < 3秒（首字节） |
| BR3.8.1.5 | 支持HTTP Range请求，支持断点续传 |
| BR3.8.1.6 | 下载完成后自动记录审计日志 |

##### F3.8.2 批量下载

**功能描述：**

支持用户批量下载多个文件，系统自动将文件打包为ZIP格式。批量下载功能适用于需要导出多个文件进行离线分析的场景。

**业务规则：**

| 规则编号 | 规则描述 |
|---------|---------|

| BR3.8.2.2 | 批量下载总大小不超过10GB |
| BR3.8.2.3 | 系统自动打包为ZIP格式，支持密码保护 |
| BR3.8.2.4 | 打包过程异步执行，完成后通知用户 |
| BR3.8.2.5 | 打包文件保留7天后自动删除 |
| BR3.8.2.6 | 每个文件单独记录审计日志 |

##### F3.8.3 断点续传下载

**功能描述：**

支持下载中断后从断点继续下载，避免重复传输。断点续传下载对于大文件下载尤为重要，可以显著提升用户体验。

**业务规则：**

| 规则编号 | 规则描述 |
|---------|---------|

| BR3.8.3.2 | 客户端记录已下载字节位置 |

**功能描述：**

支持下载速率限制，防止下载占用过多带宽资源。限流下载可以保障平台的整体性能稳定。

**业务规则：**

##### F3.8.5 下载审计

**功能描述：**

记录所有下载行为，包括下载人、下载时间、下载文件、来源IP、下载结果等。下载审计是数据安全的重要保障，可以追溯文件的外发行为。

### 3.9 文件管理模块

#### 3.9.1 模块概述

文件管理模块提供文件的删除、移动、复制、重命名、回收站、彻底删除等操作能力。该模块是文件全生命周期管理的重要组成部分，确保文件的可管理性和可追溯性。

#### 3.9.2 功能列表

| 功能编号 | 功能名称 | 优先级 | 功能描述 |
|---------|---------|-------|---------|
| F3.9.1 | 软删除 | P0 | 文件删除时移入回收站，可恢复 |
| F3.9.2 | 硬删除（彻底删除） | P0 | 从回收站彻底删除文件，不可恢复 |
| F3.9.3 | 移动文件 | P0 | 将文件移动到其他目录 |
| F3.9.4 | 复制文件 | P0 | 复制文件到其他目录 |
| F3.9.5 | 重命名文件 | P0 | 修改文件名 |
| F3.9.6 | 回收站管理 | P0 | 查看回收站文件，支持恢复和彻底删除 |
| F3.9.7 | 批量操作 | P1 | 支持批量删除、移动、复制 |

#### 3.9.3 详细功能说明

##### F3.9.1 软删除

**功能描述：**

用户删除文件时，文件不会立即从存储中删除，而是移入回收站，可以在一定期限内恢复。软删除机制可以防止用户误删文件造成数据丢失。

**业务规则：**

| 规则编号 | 规则描述 |
|---------|---------|
| BR3.9.1.1 | 删除文件时，文件状态改为"已删入回收站" |
| BR3.9.1.2 | 回收站文件保留30天，超期自动彻底删除 |
| BR3.9.1.3 | 回收站文件不占用目录展示，但在回收站可见 |
| BR3.9.1.4 | 软删除操作记录审计日志 |
| BR3.9.1.5 | 用户可软删除自己的文件，红方管理员可软删除租户内所有文件 |

##### F3.9.2 硬删除（彻底删除）

**功能描述：**

从回收站彻底删除文件，释放存储空间。硬删除操作不可逆，需谨慎执行。

**业务规则：**

| 规则编号 | 规则描述 |
|---------|---------|
| BR3.9.2.1 | 硬删除前需二次确认 |
| BR3.9.2.2 | 硬删除操作需红方管理员或系统管理员权限 |
| BR3.9.2.3 | 硬删除时采用引用计数，仅当引用为0时删除物理文件 |
| BR3.9.2.4 | 硬删除后保留元数据记录（标记为已删除），用于审计 |
| BR3.9.2.5 | 硬删除操作记录详细审计日志 |
| BR3.9.2.6 | L4/L5级文件硬删除需二次审批 |

##### F3.9.3 移动文件

**功能描述：**

将文件从一个目录移动到另一个目录。移动操作不改变文件内容，仅改变文件的所属目录。

**业务规则：**

| 规则编号 | 规则描述 |
|---------|---------|
| BR3.9.3.1 | 移动文件需对目标目录有写权限 |
| BR3.9.3.2 | 移动操作不改变文件ID和版本 |
| BR3.9.3.3 | 移动操作记录审计日志 |
| BR3.9.3.4 | 支持跨目录移动，不支持跨租户移动 |

##### F3.9.4 复制文件

**功能描述：**

复制文件到其他目录，生成新的文件记录。复制操作会创建新的文件ID，但物理存储通过引用计数共享。

**业务规则：**

| 规则编号 | 规则描述 |
|---------|---------|
| BR3.9.4.1 | 复制操作生成新的文件ID和元数据 |
| BR3.9.4.2 | 物理存储通过引用计数共享，不重复存储 |
| BR3.9.4.3 | 复制后新文件继承原文件的标签和分级 |
| BR3.9.4.4 | 复制操作记录审计日志 |

##### F3.9.5 重命名文件

**功能描述：**

修改文件名，不改变文件内容和其他属性。

**业务规则：**

| 规则编号 | 规则描述 |
|---------|---------|
| BR3.9.5.1 | 新文件名需符合命名规范（不超过255字符，不含特殊字符） |
| BR3.9.5.2 | 同目录下文件名不能重复 |
| BR3.9.5.3 | 重命名记录审计日志 |
| BR3.9.5.4 | 重命名生成新版本记录 |

##### F3.9.6 回收站管理

**功能描述：**

提供回收站管理功能，用户可以查看回收站中的文件，支持恢复和彻底删除。

**业务规则：**

| 规则编号 | 规则描述 |
|---------|---------|
| BR3.9.6.1 | 回收站按用户隔离，普通用户只能查看自己删除的文件 |

| BR3.9.6.6 | 回收站存储单独计费，避免占用主存储配额 |

##### F3.9.7 批量操作

**功能描述：**

支持批量删除、移动、复制文件，提升管理效率。

**业务规则：**

| BR3.9.7.2 | 批量操作支持进度显示和结果报告 |

| BR3.9.7.5 | 批量操作记录审计日志 |

### 4.9 API限流设计

#### 4.9.1 限流策略

平台所有API均实施限流策略，采用**用户级+租户级+IP级**三重限流，防止恶意调用和资源耗尽。

| API类别 | 接口示例 | 用户级限流 | 租户级限流 | IP级限流 | 限流策略 |
|---------|---------|----------|----------|---------|---------|
| 文件上传API | /api/v1/upload/* | 100 QPS | 500 QPS | 200 QPS | 令牌桶 |
| 检索API | /api/v1/search/* | 200 QPS | 1000 QPS | 500 QPS | 滑动窗口 |
| 下载API | /api/v1/download/* | 50 QPS | 200 QPS | 100 QPS | 令牌桶 |
| 分析API | /api/v1/analysis/* | 10 QPS | 50 QPS | 20 QPS | 令牌桶 |
| 文件管理API | /api/v1/files/* | 50 QPS | 200 QPS | 100 QPS | 滑动窗口 |
| 任务管理API | /api/v1/tasks/* | 50 QPS | 200 QPS | 100 QPS | 滑动窗口 |
| 系统配置API | /api/v1/system/* | 20 QPS | 50 QPS | 30 QPS | 滑动窗口 |
| 默认API | 其他 | 30 QPS | 100 QPS | 50 QPS | 滑动窗口 |

#### 4.9.2 限流响应

当请求触发限流时，系统返回 HTTP 429 状态码和限流错误码：

```json
{
  "code": 9008,
  "message": "请求频率超限",
  "detail": "当前QPS: 101, 限制: 100 QPS",
  "retry_after": 1,
  "request_id": "req-xxxx-xxxx-xxxx"
}
```

#### 4.9.3 限流规则

| 规则编号 | 规则描述 |
|---------|---------|
| BR4.9.1 | 限流策略基于Redis实现，支持用户级/租户级/IP级三层限流 |
| BR4.9.2 | 用户级限流优先触发，未触发时检查租户级，最后检查IP级 |
| BR4.9.3 | 触发限流时返回 HTTP 429 + 错误码 9008，并返回 retry_after 建议重试时间 |
| BR4.9.4 | 限流策略可由系统管理员动态配置，无需重启服务 |
| BR4.9.5 | 租户级限流支持按租户套餐差异化配置（基础版/专业版/企业版） |
| BR4.9.6 | 限流统计按滑动窗口（1秒）计算，避免瞬时流量尖峰误判 |
| BR4.9.7 | 检索API采用滑动窗口，上传/下载/分析API采用令牌桶，平衡突发与公平 |
| BR4.9.8 | 限流触发时记录审计日志，连续触发告警通知系统管理员 |

## 7. 验收标准

### 7.1 文件上传模块验收标准

#### AC-3.1.1 单文件上传

```
Given 红方操作员已登录系统，且拥有上传权限
When 操作员选择一个100MB的PCAP文件并点击上传
Then 文件上传成功，返回文件ID，文件状态为"已上传"
And 文件元数据（名称、大小、类型、哈希）正确记录到数据库
And 上传完成后自动触发文件解析任务
And 审计日志记录：用户ID、操作时间、文件名、文件大小、上传结果
```

#### AC-3.1.2 分片上传（断点续传）

```
Given 红方操作员上传一个2GB的大文件，分片大小10MB
When 上传到第100片时网络中断
Then 系统保留已上传的100个分片
When 操作员重新发起上传请求
Then 系统从第101片继续上传，无需重新上传前100片
And 所有分片上传完成后，系统合并分片并校验整体SHA256+SM3哈希
And 哈希校验通过后，文件状态变更为"已上传"
```

#### AC-3.1.3 秒传上传

```
Given 租户A的用户已上传文件file.txt，文件SHA256为abc123
When 租户A的另一个用户上传相同内容的file_copy.txt
Then 客户端计算SHA256后查询服务端，命中已有文件
Then 系统返回秒传成功，建立文件引用关系
And 不产生实际文件传输，上传耗时 < 3秒
And file_copy.txt与file.txt共享底层存储，但元数据独立
```

```
Given 租户A的已上传文件file.txt
When 租户B的用户上传相同内容的file.txt
Then 租户隔离生效，秒传不跨租户命中
Then 租户B用户进入正常分片上传流程
```

### 7.2 文件下载模块验收标准

#### AC-3.8.1 单文件下载

```
Given 红方操作员已登录，且拥有目标文件的下载权限
When 操作员点击下载按钮
Then 系统验证权限和数据分级后，返回文件流
And 下载首字节响应时间 < 3秒
And 支持HTTP Range请求，支持断点续传
And 下载完成后自动记录审计日志（用户/时间/IP/文件ID/大小/结果）
```

#### AC-3.8.2 L4/L5文件下载审批

```
Given 红方操作员请求下载L4（机密）级文件
When 系统检测到数据分级为L4
Then 下载请求被拦截，自动发起审批流程
And 通知红方管理员有待审批的下载请求
When 红方管理员审批通过
Then 操作员收到通知，可在24小时内下载该文件
And 下载链接24小时后自动失效
```

### 7.3 文件检索模块验收标准

#### AC-3.3.1 混合检索响应时间

```
Given 系统中已索引100万份文件
When 用户执行一次混合检索（全文+元数据+向量语义）
Then 检索结果在P99 < 500ms内返回
And 结果按相关性排序，包含匹配高亮
And 返回结果总数、分页信息、各维度命中数
```

```
Given 系统检索响应时间持续超过500ms（P99）
When 监控系统检测到性能阈值超标
Then 触发告警，通知系统管理员
And 告警级别为"警告"
When 检索响应时间持续超过800ms（P99）
Then 告警级别升级为"严重"
And 通知系统管理员和红方管理员
```

#### AC-3.3.2 索引延迟

```
Given 用户上传一份新文件并完成解析
When 文件解析完成
Then 元数据索引在5秒内可检索到
And 全文索引在60秒内可检索到
And 向量索引在120秒内可检索到
```

### 7.4 权限管理模块验收标准

#### AC-3.6.1 MFA强制启用

```
Given 红方管理员账号未启用MFA
When 红方管理员尝试登录系统
Then 登录失败，提示"管理员账号必须启用MFA"
And 系统引导用户完成MFA绑定流程
When 用户完成MFA绑定（TOTP/短信/硬件Key）
Then 后续登录需输入MFA验证码
And MFA验证通过后方可进入系统
```

#### AC-3.6.2 多租户数据隔离

```
Given 租户A的用户上传文件file_A.txt
When 租户B的用户执行文件检索
Then 检索结果不包含file_A.txt
And 租户B用户无法通过文件ID直接访问file_A.txt
And 数据库查询SQL自动附加tenant_id过滤条件
```

#### AC-3.6.3 国密算法支持

```
Given 系统启用国密合规模式
When 用户上传文件
Then 文件哈希同时计算MD5、SHA256和SM3
And 审计日志使用SM2签名确保不可篡改
And 敏感数据（L4/L5）使用SM4加密存储
And API请求支持SM2签名验证
```

### 7.5 任务管理模块验收标准

#### AC-3.14.1 任务状态流转

```
Given 红方管理员创建一个新任务，状态为"待开始"
When 管理员指定负责人并点击"开始任务"
Then 任务状态变更为"进行中"
When 负责人完成任务并点击"提交"
Then 任务状态变更为"待审核"
When 管理员审核通过
Then 任务状态变更为"已完成"
And 通知任务成员任务已完成
```

```
Given 任务处于"进行中"状态
When 负责人点击"取消任务"并确认
Then 任务状态变更为"已取消"
And 通知所有任务成员
And 关联的文件和目标保留不变
```

```
Given 文件report.docx有3个版本（v1.0、v1.1、v1.2），当前为v1.2
When 用户选择回滚到v1.0

```
